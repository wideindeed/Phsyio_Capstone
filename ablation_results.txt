WHAT WAS DONE
--------------
Script: scripts/normalization_ablation.py
For every UI-PRMD-trained PhysioVision model, loaded the model's held-out
test split and ran it twice through the frozen, already-trained model:
  (a) "with normalization" -- the exact pelvis/spine-anchor centering +
      bone-length scaling the model was trained with (per-exercise, copied
      verbatim from src/engine.py / the *_analyzer.py files).
  (b) "without normalization" -- the identical raw skeleton coordinates,
      reshaped only, no centering, no scaling.
Same model weights, same test samples, only the preprocessing step toggled.
Metrics: R^2 and MAE (sklearn.metrics), predicted vs. ground-truth score.

DATA SOURCE MAPPING (scripts/download_deeprehabpile.py)
----------------------------------------------------------------------------
Data pulled from DeepRehabPile's UI-PRMD regression mirror
(https://maxime-devanne.com/datasets/RehabPile/UIPRMD_reg/<ABBR>/).
Deep Squat/STS/Shoulder Extension/Shoulder Scaption map to UI-PRMD by name
(DS/STS/SSE/SSS). Lateral Raise -> SSA confirmed via a code comment in
engine.py. Knee Extension -> SASLR, Wall Push-Up -> Inline Lunge (IL), and
Hip March -> Hurdle Step (HS) were confirmed by an EXACT match between each
analyzer's hardcoded TIME_STEPS constant and each UI-PRMD sub-exercise's
frame count (a reliable fingerprint: knee_extension_analyzer.py TIME_STEPS=63
== SASLR T=63; wall_pushup_analyzer.py TIME_STEPS=77 == IL T=77, NOT SSIER's
T=74 as first guessed; hip_march_analyzer.py TIME_STEPS=69 == HS T=69).
Bicep Curl and Push-Up were excluded (hand-collected dataset / not part of
the UI-PRMD-trained set).

VERIFICATION PERFORMED BEFORE TRUSTING THIS RESULT
----------------------------------------------------------------------------
1. DATA LEAKAGE CHECK (this caught a real bug in the first attempt):
   Checked whether each UI-PRMD exercise's fold2 test split is actually
   disjoint from fold0's train split (fold0 train is what train.py/the
   original training scripts use). Result: EVERY sample in every exercise's
   fold2 test split is an EXACT duplicate of a sample already inside
   fold0's train split (checked via np.allclose, 100% match rate across all
   8 exercises). This is because these are standard k-fold CV files: fold0's
   train = union of folds 1-4's test splits. So evaluating a fold0-trained
   model against fold2's "test" data (as scripts/evaluate_fold.py does) is
   NOT a held-out evaluation -- the model already trained on that exact data.
   FIX: switched to fold0's OWN test split (x_test_fold0.npy), which IS
   genuinely disjoint from fold0's train split (checked the same way:
   0 duplicates found across all 8 exercises). This is the only split in
   the downloaded data that is truly unseen by a fold0-trained model.
   Residual caveat: fold0's test split was passed as `validation_data` to
   Keras during original training (per train.py) and used for
   checkpoint/best-epoch selection (ModelCheckpoint monitor='val_mae'). It
   was not backpropagated on, but it did influence which epoch's weights
   got saved -- a mild, standard form of model-selection leakage, not
   train/test duplication. Worth knowing, not a reason to distrust the
   result below.
2. SPOT-CHECKED ACTUAL PREDICTIONS (Sit to Stand, fold0 test, 8 samples):
   With normalization, predictions tracked ground truth closely (e.g. true
   0.936 -> pred 0.915; true 0.923 -> pred 0.948). Without normalization,
   predictions collapsed to a narrow near-constant band (~0.57-0.59)
   regardless of the true score varying 0.906-0.936 -- i.e. the model
   saturates to a fixed output because raw world-coordinate magnitudes are
   wildly outside the ~unit scale it was trained on. This is the expected,
   mechanistically sensible failure mode of removing normalization, not a
   code bug or an artificially rigged comparison.
3. Confirmed MAE-with-normalization values are in the same ballpark as the
   model's known behavior (sanity, not identity, since fold0-test differs
   from whatever split the original report table used).
4. R^2 sensitivity caveat: UI-PRMD ground-truth scores for a given exercise
   sit in a narrow band (e.g. STS fold0-test y ranges 0.780-0.951), so R^2
   here is somewhat sensitive to small absolute errors -- flagged for
   context, does not change the qualitative with/without-normalization gap.

HEADLINE FINDING (verified, fold0-test, genuinely held out)
----------------------------------------------------------------------------
Normalization is not a cosmetic design choice. Removing it collapses R^2 to
zero or below (worse than predicting the mean score) for every single one
of the 8 UI-PRMD-trained exercises, and catastrophically so for Deep Squat
(R^2 -33.5) and Sit to Stand (R^2 -28.3). This holds even though the
comparison used the SAME model weights and SAME test samples in both arms
-- the only variable changed was the presence/absence of the pelvis/spine
anchor normalization step. Strong, defensible support for the pelvis-anchor
design decision.
